# Единая модель сессий и устройств (#706)

`auth.sessions` — источник состояния авторизации и метаданных устройства.
Каждый вход (пароль, регистрация или QR) создаёт отдельную сессию с UUID `id`
и уникальным отпечатком `access_token_hash`. Rust добавляет случайный `jti`
в каждый токен: два входа в одну секунду тоже независимы. Сырые токены в БД
не сохраняются. Смена имени устройства не меняет ID сессии.

`GET /auth/sessions` и `GET /users/devices` читают одни и те же активные
сессии, возвращают одинаковые ID и порядок. `firstLogin` в devices — это
`createdAt` сессии. `isCurrent` вычисляется по cookie конкретного запроса,
не хранится глобально. User-Agent и IP — только метаданные, не ключ поиска
сессии. `POST /users/devices/register` обновляет существующую сессию токена,
возвращая её ID; не создаёт отдельной записи и не затрагивает другие устройства.

`DELETE /users/devices/{sessionId}` отзывает выбранную сессию пользователя.
Отзыв сессии, запись отпечатка в `auth.revoked_tokens` и `pg_notify` выполняются
в одной транзакции. После commit HTTP-проверка отклоняет её токен, а все chat
реплики закрывают связанные сокеты, включая простаивающие. Проверки при
сообщениях и heartbeat покрывают пропущенное уведомление. Метаданные остальных
сессий не меняются. Чужой или неактивный ID возвращает 404, текущий — 409;
для выхода из текущей сессии используется `/auth/logout`.

`POST /users/devices/terminate-all` отзывает остальные сессии, сохраняя
сессию запроса. `/auth/logout-all` сохраняет прежнюю семантику: увеличивает
поколение токенов пользователя, отзывает все сессии, очищает cookie и push.

## Миграция и выкладка

1. Сначала выкатить Rust crypto с уникальным `jti`.
2. Остановить старые auth/user реплики: смешанная работа старой двойной записи
   с новой моделью не поддерживается. Применить `0039_canonical_device_sessions.sql`
   штатным мигратором перед запуском новых сервисов.
3. Миграция сохраняет `auth.sessions.id`, переносит метаданные только по явной
   старой связи `device_session_id` с проверкой владельца, затем удаляет связь.
   Записи без отпечатка access token помечаются отозванными. Сопоставление по
   User-Agent/IP не выполняется: оно смешало бы разные устройства.
4. Обновить все Go-сервисы, использующие общий DBTokenChecker, включая chat.
   Новые auth/user readiness-проверки требуют канонические поля метаданных.
5. Обновить открытые списки устройств на клиентах: старые legacy device UUID
   больше не являются API ID. Токены, уже имеющие запись в `auth.sessions`,
   продолжают работать; для старых токенов без такой записи нужен повторный вход.

`public.user_sessions` остаётся только замороженным legacy-снимком для
импортера. Runtime-сервисы её не читают и не записывают. Активные сессии
никогда не создаются из legacy-строк без достоверной привязки к токену.
Миграция выдерживает повторный запуск, включая прогон всей цепочки миграций
на базе без журнала `schema_migrations`.

Проверки: интеграционные тесты `internal/platform/authctx` проходят оба HTTP API
с двумя одинаковыми браузерами, стабильные ID, отзыв, logout-all и отсутствие
двойной записи; `internal/chat` проверяет закрытие сокетов выбранного устройства
на двух репликах; `cmd/migrate` — backfill и повторяемость миграции. Rust-тест
проверяет уникальность токенов последовательных входов.
