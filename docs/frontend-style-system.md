# Где живут стили

Правила размещения стилей во фронтенде. Приняты 29 августа 2026 по итогам аудита — `audits/styles-audit-2026-08-28.md`.

Аудит показал десять проблем: 20 классов объявлены в нескольких файлах, у 10 из них конфликт значений; девять `!important`; 48 мёртвых классов; четыре мобильных порога; три системы токенов; шесть разных розовых за историю проекта.

Все десять — следствия одного: **правило лежит далеко от разметки**. Поэтому система не раскладывает стили по папкам аккуратнее, а убирает это расстояние.

---

## Правило первое: стиль живёт в разметке

Стили компонента пишутся утилитами прямо в его `className`. Отдельного CSS-файла у компонента нет.

```tsx
<section className="bg-sheet border border-line rounded-bubble p-4 shadow-[var(--elev-1)]">
  <h2 className="text-title font-semibold text-ink">Название</h2>
  <p className="text-caption text-ink-2 mt-1">Подпись</p>
</section>
```

Так видно, что применено, прямо там, где применено. Ничего не перебивает друг друга: у утилит нет глобальных имён, которые могли бы столкнуться.

### Где лежит компонент

Своя папка в `components/ui/`, внутри сам компонент, его тесты и `index.ts`:

```
components/ui/Button/
  Button.tsx
  Button.test.tsx
  index.ts
```

**Пропсы объявляются внутри файла компонента** и называются `Props`. Наружу не экспортируются: за пределами компонента они никому не нужны, а лежащий рядом `Props` не может столкнуться с чужим.

В `types/*.types.ts` живут только доменные типы — то, что ходит между сервисами, запросами и разметкой: `IChatDto`, `IMessageDto`, события сокета, ответы API.

### Что остаётся в файлах

```
styles/tokens/           палитра, схемы оформления, шкалы, темы
styles/base.css          сброс, типографика, поведение голых элементов
styles/keyframes.css     анимации — их Tailwind не выражает
```

Больше ничего. Ни свода на полторы тысячи строк, ни файла на страницу, ни пяти файлов на раздел.

## Правило второе: состояния через `data-*`, а не классы

```tsx
<button
  data-state={active ? 'active' : undefined}
  className="text-ink-2 data-[state=active]:bg-brand-soft data-[state=active]:text-brand"
>
```

Почему не классы. В проекте состояния записаны четырьмя способами сразу: `is-active`, `has-media`, голое `active`, голое `open`. При этом `.active` объявлен в четырёх файлах и означает в них разное — какое правило победит, решает случайный порядок импорта.

У `data-state` нет глобального имени, сталкиваться нечему. Разнобой становится невозможен, а не нежелателен.

Значения атрибута — по смыслу: `active`, `open`, `loading`, `error`. Не `true`.

## Правило третье: `@apply` не используется

Он возвращает ровно ту проблему, от которой избавляют утилиты: правило снова далеко от разметки, и снова не видно, что сломается при правке. В документации Tailwind назван крайним средством.

Сейчас в проекте 293 использования. Они исчезнут вместе с классами, которые их содержат.

---

## Правило четвёртое: пороги только от Tailwind

`md:` — это и есть 768 пикселей.

```tsx
<div className="flex-col md:flex-row">
```

Ручной `@media` допустим ровно в двух случаях: `prefers-color-scheme` и `prefers-reduced-motion`. Всё остальное — приставки Tailwind.

В проекте сейчас четыре разных порога: 760, 768, 769 и 900. И 47 ручных запросов, дублирующих `md`.

---

## Правило пятое: `style={{ }}` только для вычисляемого

Допустимо: ширина полосы прогресса, цвет аватарки по идентификатору, положение всплывающего меню.

Недопустимо: любое значение, известное заранее. Для него есть утилита или токен.

---

## Правило шестое: цвет только из токенов

Ни одного `#hex` и ни одного `rgba()` за пределами `styles/tokens/palette.css`.

Нужного оттенка нет — это повод обсудить палитру, а не дописать значение на месте. Именно так в проекте завелись шесть разных розовых, каждый из которых означал фирменный цвет.

Сырые значения палитры (`--neutral-panel`, `--brand-fill` и подобные) в разметке не появляются: для них намеренно не созданы утилиты, класса `bg-neutral-panel` не существует. Компонент знает назначение (`bg-sheet`), а не цвет.

### Темы, палитры, акценты

Внешний вид задают три атрибута на `<html>`, и каждый меняет только своё:

| Атрибут | Значения | Что меняет |
|---|---|---|
| `data-theme` | `light`, `dark` | всё, что зависит от темы |
| `data-palette` | нет (графит), `midnight`, `warm` | только нейтральные цвета: поверхности, линии, текст |
| `data-accent` | нет (фиолетовый), `plum`, `orchid`, `indigo`, `amber`, `teal` | только акцент и свой пузырь |

Значения — из дизайн-системы редизайна (`docs/redesign.md`), в формате Tokens Studio они же лежат в `docs/ui-kit.tokens.json`. Контраст пар «текст на фоне» во всех 36 сочетаниях и то, что палитра и акцент не трогают чужие токены, проверяет `styles/tokens/contrast.node.test.ts`: правка значения, которая роняет контраст, не пройдёт тесты.

### Имена в дизайн-системе и в коде

Большинство имён совпадает. Где нет — в коде осталось старое имя, потому что компоненты на нём уже держатся, а роль та же:

| Дизайн-система | Утилита | Роль |
|---|---|---|
| `ground` | `bg-ground` | фон окна за панелями |
| `panel` | `bg-sheet` | панели, карточки |
| `raised` | `bg-sheet-2` | приподнятое: плитки, вторичные кнопки |
| `chat-bg` | `bg-chat-bg` | лента, поля ввода |
| `composer` | `bg-composer` | карточка поля ввода |
| `menu` | `bg-menu` | меню, всплывающие окна, диалоги |
| `line` | `border-divider`, `bg-line-soft` | разделители, дорожки |
| — | `border-line` | очертание элемента управления, ≥ 3:1; в дизайн-системе его нет |
| `ink`, `ink-2`, `ink-3` | `text-ink`, `text-ink-2`, `text-ink-3` | текст |
| `brand` | `text-brand` | акцент как текст |
| `fill` | `bg-brand-fill` | акцент как заливка |
| `on-fill` | `text-on-brand` | текст на заливке |
| `soft` | `bg-brand-soft` | мягкая подложка акцента |
| `out-meta` | `text-out-meta` | время и галочки на заливке |
| `ok`, `warn`, `danger`, `info` и `*-soft` | те же имена | состояния |
| `rec`, `hover`, `press`, `hl`, `muted-badge`, `spoiler` | те же имена | запись, подсветки, счётчик без звука, спойлер |
| `hl-cur` | `bg-hl-current` | текущее совпадение поиска |
| `scrim` | `bg-backdrop` | затемнение под диалогом; `scrim-*` заняты подложками поверх медиа |
| `call-ground`, `call-accept`, `call-decline` | `bg-call-ground`, `bg-call-accept`, `bg-call-reject` | звонок |

Тени дизайн-системы — переменные `--shadow-menu`, `--shadow-composer`, `--shadow-tab`, `--shadow-card`, в разметке через `shadow-[var(--shadow-menu)]`: утилита `shadow-*` из `@theme` подставляет значение, и подмена по теме не сработала бы. Скругления и шкала текста названы по назначению, а не по величине: имена `sm`/`md`/`lg` заняты у Tailwind, и переопределить их значило бы сдвинуть всё, что уже свёрстано.

| Дизайн-система | Утилита | Где |
|---|---|---|
| `radius-xs` 6 | `rounded-control` | угол пузыря со стороны автора, код в тексте |
| `radius-sm` 10 | `rounded-field` | пункт меню, маленькая кнопка, сегмент |
| `radius-md` 12 | `rounded-icon` | кнопка-иконка |
| `radius-lg` 14 | `rounded-button` | кнопка, поле формы, переключатель |
| `radius-xl` 16 | `rounded-bubble` | строка списка, меню, пузырь |
| `radius-2xl` 18 | `rounded-dialog` | диалог, плашка |
| `radius-3xl` 20 | `rounded-window` | поле ввода сообщения, пост, панель |
| `radius-card` 28 | `rounded-card` | карточка входа |
| `meta` 12 · `body` 14 · `body-lg` 15 · `title-sm` 16 · `title-lg` 20 | `text-meta` · `text-ui` · `text-body` · `text-subtitle` · `text-section` | остальные размеры текста совпадают по имени |

Новое имя шкалы добавляется и в `shared/lib/utils/cn.ts`: иначе tailwind-merge не знает, с чем оно спорит, и молча выбрасывает размер шрифта.

### Наведение и нажатие

Слоем поверх фона, а не заменой: `hover:layer-hover active:layer-press`. Отмеченный пункт меню и выбранная строка при наведении сохраняют свою подложку. Утилиты объявлены в `tailwind.css`; погасить слой там, где он не нужен, — `hover:bg-none`.

### Кнопка

| Дизайн-система | `Button` |
|---|---|
| `primary` | `variant="primary"` |
| `secondary` | `variant="secondary"` |
| `ghost` — ссылка-действие цветом акцента | `variant="accent"` |
| «Отмена» без фона, кнопка-иконка | `variant="ghost"` |
| `danger` | `variant="danger"` |
| `--sm` | `size="sm"` |

Эмодзи в тексте рисует Noto Color Emoji — он стоит вторым в `--font-sans`, сразу за Geologica, и грузится с Google Fonts вместе с остальными шрифтами.

## Исключения

Свой CSS-файл рядом с компонентом допустим там, где разметка сложная и утилиты нечитаемы. Список закрытый, пополняется через обсуждение:

| Компонент | Почему |
|---|---|
| `media-editor/PhotoEditorModal` | Холст, кадрирование, ручки изменения размера — геометрия, а не оформление |

Файл в исключении всё равно подчиняется правилу шестому: цвет только из токенов.

---

## Чем проверяется

ESLint с плагином под Tailwind. В проекте его сейчас нет вовсе — только Prettier, — поэтому заводится отдельной задачей.

Что должен ловить:

- неизвестные классы (опечатки вроде `duration-fast`, которого не существовало);
- конфликтующие утилиты в одном `className`;
- `style={{ }}` со статическим значением.

До этого — ревью и настоящий документ.

---

## Как переходим

По одному экрану. Экран переводится целиком: стили уезжают в разметку, его CSS-файл или раздел свода удаляется.

**Кроме элементов управления.** Кнопки, поля, выпадающие списки и переключатели остаются классами до появления компонентов (#339): переносить их в разметку сейчас значит через неделю переносить обратно, уже в `<Button>`. Такие правила помечены в CSS комментарием с номером задачи.

Старый блок `@theme` в `tailwind.css` уходит последним, когда исчезнет последняя из 47 ссылок на него.

### Как выглядит готовый экран

- ни одного своего класса, кроме элементов управления в ожидании компонентов;
- ни одного `#hex` и `rgba()`;
- ни одного ручного `@media`;
- состояния через `data-*`;
- раздел свода, относившийся к экрану, удалён.
