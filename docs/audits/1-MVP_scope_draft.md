# 17. Технические требования MVP

## 17.1. Авторизация

- Не хранить основной access token в `localStorage`
- Перейти на безопасную схему авторизации
- Предпочтительно использовать:
  - `HttpOnly`
  - `Secure`
  - `SameSite`
  - cookie-based auth

## 17.2. WebSocket

- Не передавать основной bearer token в URL WebSocket
- При одном origin frontend/backend рассмотреть cookie-auth для WebSocket handshake
- Проверять `Origin`
- Logout должен закрывать активный WebSocket
- Logout-all должен закрывать все активные WebSocket-соединения пользователя

## 17.3. Read receipts

- Один и тот же подтверждённый messageId не должен многократно отправляться в `/messages/read`
- Несколько новых read-событий должны батчиться
- Rerender не должен создавать повторные запросы
- Refetch не должен создавать повторные запросы
- Reconnect не должен создавать лавину повторных запросов
- Backend должен учитывать конкретные `messageIds`
- Точное время прочтения должно сохраняться и отображаться

## 17.4. Надёжность

- Корректное поведение при потере сети
- Корректный reconnect
- Отсутствие дубликатов
- Корректная обработка ошибок API
- Отсутствие необработанных критических ошибок
- Корректное восстановление состояния после перезагрузки страницы

# 20. Известные GAP / проблемы

- Нет общей истории звонков
- Нет API изменения username
- Device/session модель не связана корректно с авторизацией
- Удаление устройства не отзывает bearer token
- Web Push не реализован
- Privacy применяется не во всех сценариях
- Язык / локализация требуют проверки
- Read receipts работают некорректно
- Есть повторные `/messages/read`
- Access token хранится в `localStorage` в проверенной старой версии
- Основной bearer token передаётся в WebSocket URL в проверенной старой версии
