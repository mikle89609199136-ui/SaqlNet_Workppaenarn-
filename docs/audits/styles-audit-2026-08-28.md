# Аудит стилей фронтенда

28 августа 2026. Состояние на `dev` после перевода экранов на токены.

Задача документа — зафиксировать, **где сейчас живут стили и что из этого устроено неправильно**. Решений о том, как должно быть, здесь нет: они принимаются отдельно, на основании этих фактов.

Все числа получены измерением, а не оценкой на глаз.

---

## 1. Где живут стили

Семь разных мест.

| Где | Объём | Чем является |
|---|---|---|
| `styles/tailwind.css` | 1413 строк | Основной свод. Внутри `@layer components` с 293 `@apply` |
| `styles/ChatThreadPage.css` | 508 строк | Обычный CSS, отступы табами. Импортируется страницей треда |
| `styles/Settings*.css` | 796 строк в 5 файлах | Связаны цепочкой через `SettingsPage.css` |
| `design-system/tokens/*.css` | 447 строк в 6 файлах | Новая система токенов |
| `components/.../PhotoEditorModal.css` | 11 строк | **Единственный** файл рядом с компонентом |
| `className` в разметке | 297 вхождений утилит | В 14 файлах из 72 |
| `style={{ }}` в разметке | 24 вхождения | В 8 файлах |

**Точки импорта не собраны в одном месте.** Стили подключаются из шести файлов: `main.tsx`, `ChatThreadPage.tsx`, `SettingsPage.tsx`, `SettingsSidebar.tsx`, `SettingsDetailPage.tsx`, `PhotoEditorModal.tsx`. Порядок подключения нигде не задан, а от него зависит, какое правило победит.

## 2. Один класс объявлен в нескольких файлах

**20 классов** объявлены больше чем в одном файле. У **10 из них** — настоящий конфликт: одно и то же свойство задано разными значениями.

Кто победит, определяется порядком импорта, а он случаен. Из кода это не видно.

### Примеры

**`.active` — четыре файла**

| Файл | Цвет | Фон |
|---|---|---|
| `tailwind.css` | `--color-brand` | `--color-brand-soft` |
| `ChatThreadPage.css` | `--color-ink` | `--color-line` |
| `SettingsControls.css` | — | `--color-sheet-2` |
| `SettingsSidebar.css` | `--text-primary` | смесь с акцентом |

Четыре разных представления о том, как выглядит «выбранное».

**`.is-active` — три файла**

```
PhotoEditorModal.css   linear-gradient(135deg,#ff2d8b,#b65cff)
SettingsPage.base.css  var(--color-brand-fill)
tailwind.css           var(--color-accent)
```

Здесь же виден `#ff2d8b`. Он не единственный: по истории репозитория в проекте побывало **шесть разных розовых**, и все они означали одно и то же — фирменный цвет.

```
#ff2d8b   в 24 коммитах    #ff3366   в 7
#E91E8C   в 8              #ff007f   в 6
#d92fa9   в 4              #ff3b98   в 3
```

Никто их не выбирал: каждый следующий подбирался на глаз, когда под рукой не было предыдущего.

**`.thread-call-button` — два файла, три расхождения**

```
цвет        --color-ink       [ChatThreadPage.css]
            --color-brand     [tailwind.css]
фон         transparent       [ChatThreadPage.css]
            --color-brand-soft [tailwind.css]
переход     background-color 0.2s   [ChatThreadPage.css]
            background 0.16s …      [tailwind.css]
```

**`.thread-composer`**

```
background  transparent !important   [ChatThreadPage.css]
            var(--color-line)        [tailwind.css]
```

Полный список конфликтующих: `.active`, `.is-active`, `.is-danger`, `.app-layout`, `.thread-back`, `.thread-call-button`, `.thread-composer`, `.thread-file-input`, `.chats-toolbar`, `.settings-left-pane`.

Дублируются без конфликта: `.back-arrow-btn`, `.chats-search`, `.mobile-layout`, `.rail-tab`, `.settings-toggle-knob`, `.settings-toggle-switch`, `.thread-attachment-preview`, `.thread-call-actions`, `.thread-composer-context`, `.thread-header`.

### Чем это уже обернулось

При перекраске я покрасил `.chats-search` в `tailwind.css` и не увидел изменений на экране: версия из `ChatThreadPage.css` молча перебивала. Списал на глаз, нашёл случайно через два шага.

## 3. Девять `!important`

| Файл | Сколько |
|---|---|
| `SettingsPage.base.css` | 4 |
| `ChatThreadPage.css` | 3 |
| `tailwind.css` | 2 |

Это следствие пункта 2: когда правила спорят, спор решают силой. Каждый `!important` — место, где кто-то не смог понять, почему его правило не работает.

## 4. Tailwind используется как обычный CSS

```
вхождений своих классов в разметке    457
вхождений утилит Tailwind             297
файлов, где утилиты вообще есть        14 из 72
@apply в tailwind.css                 293
```

То есть подключён Tailwind, а пишем мы на нём обычные классы. `@apply` в документации Tailwind прямо назван крайним средством: он возвращает ту самую проблему, от которой утилиты избавляют — правило далеко от разметки, и непонятно, что сломается при правке.

`ChatThreadPage.css` и файлы настроек не содержат `@apply` вовсе — это чистый CSS, приехавший из клиента до React.

## 6. Имена без системы

**71 приставка**, крупнейшие:

```
settings- 65    thread- 33    photo- 24    user- 23
message- 19     chat- 13      chats- 10    crop- 10
login- 9        app- 8        contact- 7   member- 6
```

`chat-` и `chats-` живут рядом и означают разное: первое — про один чат, второе — про список. Отличаются одной буквой.

**Состояния записаны четырьмя способами:**

```
is-*      13   (is-active, is-mine, is-online…)
has-*      2
active     2   (без приставки)
open       1   (без приставки)
```

## 7. Четыре мобильных порога

```
@media (min-width: 768px)   47 раз
@media (max-width: 768px)    4
@media (max-width: 900px)    2   ← без пробелов в записи
@media (max-width: 760px)    2
@media (min-width: 769px)    1
```

768, 769, 760 и 900 — четыре разных представления о том, где кончается мобильный экран. При этом у Tailwind есть свой `md`, равный ровно 768px, и все 47 ручных запросов его дублируют.

## 8. Две системы токенов одновременно

Старый блок `@theme` в `tailwind.css` жив и на него **всё ещё 47 ссылок**:

```
--color-accent     16 ссылок
--color-accent-2   10
--color-panel       9
--color-border      5
--color-muted       4
--color-bg          3
--color-surface     0
--color-rail        0
--color-nav         0
```

Три переменные уже ни на что не ссылаются, три указывают на новые токены, три остались со своими значениями — включая `--color-accent: #ff007f`, малиновый из прежней палитры.

Плюс восемь ссылок на `--react-*` — третий слой псевдонимов, оставшийся от миграции.

## 9. Один файл живёт по другим правилам

`PhotoEditorModal.css` — единственный CSS рядом с компонентом. Все остальные лежат в общей папке `styles/`.

Внутри него собственные значения цвета, не совпадающие ни с одной палитрой, и два класса, конфликтующих с общими (`.is-active`, `.is-danger`).

Сам по себе такой способ не хуже — колокация как раз считается хорошей практикой. Плохо то, что он **один**: правило есть, но действует в одном месте из семидесяти.

## 10. Вкрапления в разметке

24 использования `style={{ }}` в 8 файлах. Больше всего в `GroupInfoModal` (14 значений цвета) и фоторедакторе (10).

Часть из них оправдана — вычисляемые значения вроде ширины полосы или цвета по идентификатору. Часть просто перекрывает CSS.

## Что из этого следует

Все десять пунктов — следствия одного: **у стилей нет единого места и единого правила размещения**. Проект пережил переезд с обычного CSS на React с Tailwind, но стили переехали как были: файлами, именами и порядком подключения из прошлой архитектуры.

Отсюда всё остальное — дубли, `!important`, четыре порога, три системы токенов, мёртвые правила, которых не видно.
