# CraneApp — правила разработки

Документ для всех, кто работает с репозиторием: и для людей, и для агентов.
Раньше это содержимое лежало в `CLAUDE.md` в корне — файл был артефактом
конкретного инструмента и в репозитории больше не хранится (см. `.gitignore`).

## Как здесь принято работать

- **Бэкенд не трогаем.** Владелец репозитория — фронтенд-разработчик. Найденное в Go или Rust оформляется задачей для бэкенда, а не правится на месте. Это касается и `backend-v2/`, и `server/crypto-rust/`.
- **Сначала разбор, потом правка.** Описать проблему, обсудить, и только затем чинить. Молчаливое «я тут заодно поправил» не приветствуется.
- **Проверять вживую.** «Должно работать» не считается. Есть стенд и Playwright — поднять и посмотреть.
- **Проверять контракты при переносе файлов.** При перемещении модулей сразу переводить всех потребителей на новые канонические пути и валидировать контракты слоёв. Запрещено оставлять временные bridge-файлы и прокси-реэкспорты (`export * from '@/...'`) — они маскируют устаревшие импорты и создают циклические зависимости.
- **Ветки от `dev`.** `master` только для готового проверенного кода. PR в `dev`, слияние сквошем.
- **Имена в коде — латиницей.** Переменные, функции, типы, поля, параметры. Кириллица живёт в текстах: названия `describe` и `it`, сообщения утверждений, комментарии, надписи в интерфейсе. Тесты не исключение — разбирали отдельной задачей (#377).
- Общение и комментарии в задачах — по-русски.

## Команды

Все скрипты клиента живут в `frontend/`, а не в корне. Из корня проброшены только `dev`, `build:react`, `typecheck`, `test`.

```bash
cd frontend
npm run dev              # клиент на 127.0.0.1:3000
npm test                 # vitest, один прогон
npm test -- path/to.test.tsx   # один файл
npm run test:watch
npm run build
npm run typecheck        # см. ниже, сейчас падает
npm run check:cycles     # циклические импорты, dpdm
npm run format:check     # prettier по src, те же исключения, что у хука
npm run format           # то же с исправлением
npm run e2e              # playwright, тестов пока нет (#277)
```

Стенд целиком:

```bash
# ALLOWED_ORIGINS обязателен, иначе compose падает на интерполяции.
# Адреса, с которых открывается клиент (dev-сервер, `vite preview` на :4173),
# должны быть в списке: сессия — в cookie (#705), и меняющие данные запросы
# и сокет с ней принимаются только с перечисленных адресов, иначе 403.
ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://localhost:5173,http://localhost:4173 \
  docker compose -f infrastructure/docker/docker-compose.v2.yml up -d
```

Двенадцать сервисов: `postgres`, `redis`, `nats`, `minio`, `crypto` (Rust), одноразовый `migrate` (Go-мигратор из `backend-v2/cmd/migrate`, как на проде: применяет новые миграции, записывает их в `schema_migrations` и выходит) и шесть Go-сервисов из `backend-v2/cmd/` — `edge`, `auth`, `user`, `chat`, `media`, `admin`. Точка входа для клиента — `edge` на `:8080`.

Сидера в репозитории нет: на свежем стенде пользователей не будет, их заводят руками через `POST /api/v2/auth/register`.

## Устройство клиента

Слои и правило «всё серверное живёт в кеше запросов и больше нигде» подробно описаны в `docs/frontend-data-architecture.md` — читать оттуда, здесь не дублируется.

Коротко о том, что из кода не выводится:

- **Фичи друг друга не импортируют** (#863, правило в `eslint.config.js`): общее опускается в `entities`/`shared`, композиция нескольких фич — в `widgets`/`pages`, действие другой фичи приходит пропом от того, кто собирает экран.
- **`services/serviceContainer.ts`** собирает все сервисы и раздаёт их через `services`. Сервисы не держат состояние — только запросы; данные оседают в TanStack Query.
- **`realtime/`** — сокет и раскладка событий в инвалидации кеша. `invalidationMap.ts` связывает тип события с тем, что перечитать.
- **`crypto/`** — сквозное шифрование целиком на клиенте: `identity` (пара ключей ECDH и ECDSA), `chatKeys` (ключ чата с эпохами, завёрнутый под каждого участника), `envelope` (AES-GCM с привязкой к контексту), `signing`. Приватные ключи неизвлекаемые, лежат в IndexedDB. Сервер видит только шифровку.
- **Звонки** — `features/call`: модель звонка и сигналинг через общий сокет, WebRTC. Старый `call.html` в `<iframe>` удалён (#776); пока нет нового экрана разговора (#774), звонки выключены флагом `CALLS_ENABLED` (`shared/config/calls.ts`).

## Стили

Правила размещения — `docs/frontend-style-system.md`. Коротко:

- **стиль живёт в разметке**, утилитами. Отдельного CSS-файла у компонента нет;
- **состояния через `data-*`**, а не классы: `data-[state=active]:bg-brand-soft`;
- **`@apply` не используется** — он возвращает ту же проблему, от которой избавляют утилиты;
- **пороги только от Tailwind** (`md:` это 768). Ручной `@media` — лишь для `prefers-color-scheme` и `prefers-reduced-motion`;
- **`style={{ }}`** — только для вычисляемого;
- **цвет только из токенов**, ни одного hex вне палитры.

Исключения — закрытый список в том же документе.

Переход идёт по одному экрану. Элементы управления (кнопки, поля, списки, переключатели) остаются классами до появления компонентов #339 и помечены в CSS комментарием.

## Дизайн-система

Заведена в `frontend/src/styles/tokens/`, подключена, но экраны на неё **ещё не переведены** — они пользуются старым блоком `@theme` в `styles/tailwind.css`. Имена не пересекаются, наборы живут рядом, переезд идёт по одному экрану.

Пять слоёв: `palette` → `accents` → `scales` → `semantic` → `themes`.

Правила, которые легко нарушить не зная:

- **Утилитами Tailwind становится только семантика.** Ступени лесенки объявлены обычными правилами, поэтому класса `bg-n-950` не существует — так и задумано. Компонент знает назначение (`bg-sheet`), а не цвет.
- **Тени — через `shadow-[var(--elev-2)]`**, не через `shadow-*`. Утилита Tailwind подставляет значение, а не ссылку, и переопределение в тёмной теме не срабатывает.
- **Радиусы названы по назначению** (`rounded-field`, `rounded-bubble`, `rounded-window`), потому что `--radius-lg` принадлежит Tailwind и его переопределение молча ломает всё, где уже написан `rounded-lg`.
- Переменная из `@theme` попадает в CSS, **только если её кто-то использует**. Пустое значение в `getComputedStyle` не означает поломку.
- Шрифт — `Geologica`, переменный, диапазон 300–800. Выбран потому, что в `Outfit` нет кириллицы вовсе и весь русский текст рисовался системным шрифтом.

Наглядно всё это — `docs/ui-kit.html`, открывается двойным кликом.

## Грабли

- **`npx vite` без аргументов слушает `[::1]:3000`**, то есть по `127.0.0.1` не отвечает. `npm run dev` привязывается правильно. Открывать через `localhost`.
- **`DEV_API_PROXY_TARGET` должен смотреть на `127.0.0.1:8080`, а не на `localhost:8080`.** На порту 8080 у Docker Desktop два слушателя: `com.docker.backend` на IPv4 и `wslrelay` на `[::1]`. Node резолвит `localhost` в IPv6 первым, и запрос уходит в relay. После `docker compose up -d --build` relay остаётся со ссылкой на прежние контейнеры: порт держит, соединение принимает, ответа не даёт. Выглядит как вечная загрузка без единой ошибки в консоли — приложение ждёт загрузчик сессии, а `HydrateFallback` у корневого маршрута нет, поэтому вместо спиннера белый экран.
- **Концы строк — LF везде.** Git для Windows ставит `core.autocrlf=true` в системный конфиг и отдавал рабочую копию с CRLF: `gofmt -l` считал неотформатированными десятки файлов, а правки, рассчитанные на `\n`, не находили текст. Теперь `.gitattributes` (`* text=auto eol=lf`) держит LF и в рабочей копии. На уже склонированной копии он действует после пересоздания файлов: `git rm --cached -r -q . && git reset -q --hard` (на чистом дереве; неотслеживаемые файлы не трогает).
- **Prettier.** В `.prettierrc` стоит `endOfLine: "auto"`: пока не у всех рабочая копия пересоздана в LF, так prettier не ругается на CRLF. Исключения — в корневом `.prettierignore`: сгенерированные типы, контракт OpenAPI и `tailwind.css`, у каждого там указана причина. Из папки `frontend` prettier запускать через `npm run format:check`: голый `npx prettier` оттуда корневых исключений не видит.
- **`lefthook` на pre-commit прогоняет prettier по всем файлам в коммите.** При массовых переносах это даёт тысячи строк лишних изменений — тогда `--no-verify` и объяснение в теле коммита.
- **`npm run typecheck` сейчас падает**: около 600 ошибок, проверка убрана из CI (#253). Включать ступенчато, разом не выйдет.
- **`legacy/mobile-client/`** — клиент до React. Ничем не собирается и не раздаётся: `edge` отдаёт только сборку Vite из `dist/`. Заморожен, править не нужно, см. `legacy/README.md`.
- **Миграции обязаны переживать повторный прогон.** База, созданная до `schema_migrations`, при первом запуске мигратора получает все файлы подряд. Поэтому `CREATE … IF NOT EXISTS`, `DROP … IF EXISTS`, условия в `DO $ … $` — и никаких безусловных `ALTER COLUMN … TYPE`: после `0025_username_changes` на `auth.users.username` висит триггер, и Postgres отказывается менять тип такой колонки. Проверяет CI (`go test -tags=integration ./cmd/migrate`). Уже применённые миграции не правятся — кроме как ради повторяемости без изменения результата.
- Сборка клиента кладётся в **корневой `dist/`**, а не в `frontend/dist` — на этот путь рассчитывают compose и `edge`.

## Задачи

**Задачи заводит владелец репозитория.** Не создавать issues без прямой просьбы и не предлагать «оформить это задачей» по ходу работы. Нашлось что-то попутно — сказать одной строкой в ответе и на этом остановиться; решение принимает владелец. То же про подзадачи, метки и приписывание задач к эпикам.

Работа ведётся в задачах GitHub, метки обязательны: `module:*`, `type:*`, `stack:*`. Крупные разбиваются на подзадачи родным механизмом:

```bash
# нужен внутренний id, не номер, и обязательно -F (число, не строка)
ID=$(gh api repos/{owner}/{repo}/issues/340 --jq .id)
gh api -X POST repos/{owner}/{repo}/issues/339/sub_issues -F sub_issue_id=$ID
```

Процессы описаны в `docs/processes/` — постановка, разработка, git, код-ревью.
