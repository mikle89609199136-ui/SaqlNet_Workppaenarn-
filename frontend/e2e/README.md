# Пять E2E-сценариев #277

`chat.spec.ts` проверяет настоящий backend/crypto, WebCrypto и IndexedDB в двух
изолированных контекстах Chromium:

1. Обмен зашифрованными сообщениями в обе стороны; сервер получает конверт,
   а не открытый текст; приватные ключи в IndexedDB неизвлекаемы.
2. Групповое сообщение.
3. Медиа: зашифрованная загрузка и побайтово совпадающий скачанный файл.
4. Обрыв настоящего `/ws`, сообщение во время обрыва и восстановление без
   перезагрузки документа; авторизация cookie, токена в URL нет.
5. Ротация при удалении/возвращении участника группы: эпоха увеличивается,
   новая переписка работает, доступная история сохраняется после перезагрузки.

Последний пункт следует текущему контракту #707: обычная ротация сохраняет
старые ключи. Старое описание #277 о плейсхолдерах после любой ротации устарело.
Утрату личности и сброс облачной копии этот сценарий не имитирует.

## Локальный запуск

Из корня поднимите стандартный стенд:

```bash
ALLOWED_ORIGINS=http://127.0.0.1:3000 \
  docker compose -f infrastructure/docker/docker-compose.v2.yml up -d --build
npm --prefix frontend ci
(cd frontend && npx playwright install chromium)
```

Задайте тестовый пароль через окружение. На свежем локальном стенде можно
создать новую пару аккаунтов для каждого прогона:

```bash
export E2E_PASSWORD='ваш-тестовый-пароль-10+-символов'
E2E_CREATE_ACCOUNTS=1 DEV_API_PROXY_TARGET=http://127.0.0.1:8080 \
  npm --prefix frontend run e2e
```

Пароль должен удовлетворять текущей политике регистрации. Для облачной копии
используется `E2E_CLOUD_PASSWORD`, а при его отсутствии — `E2E_PASSWORD`.
Без `E2E_CREATE_ACCOUNTS=1` выполняется вход существующей тестовой пары:
`E2E_USER_A`, `E2E_USER_B`, `E2E_PASSWORD`. Их облачный пароль должен быть известен.
Аккаунты должны быть разными, без 2FA. Тесты пишут сообщения и создают группы;
используйте выделенные тестовые аккаунты.

По умолчанию Playwright запускает Vite на 127.0.0.1:3000 со строгим портом;
локально может использовать уже работающий сервер. С `E2E_BASE_URL` используется
уже запущенный клиент по этому адресу, дополнительный Vite не поднимается.
Адрес клиента должен входить в `ALLOWED_ORIGINS` backend. Для удалённого backend
за локальным Vite задайте `DEV_API_PROXY_TARGET` и разрешите origin Vite на стенде.

Подготовка получает реальные HttpOnly cookies через API и помещает только профиль
в localStorage. Резервная копия настраивается/открывается через UI; готовность
подтверждается успешной публикацией ключа, доступностью поля сообщения и
завершением загрузки/расшифровки ленты (`aria-busy=false`).
Контексты живут весь прогон, ключи создаёт приложение; storageState с подменённой
IndexedDB или криптографических моков нет. Получатель открывается первым.

Один worker. За Vite у обоих браузеров общий IP, а crypto API ограничен 30
запросами/мин: обвязка распределяет настоящие `/encryption/*` запросы с интервалом
2,1 с через `route.continue()`, без подмены ответов/повтора отказов. Поэтому полный
прогон занимает несколько минут (локально 6,8 минуты). Для ротации отведено
5 минут, для остальных сценариев — 2 минуты; ожидание готовности ключей и
истории проверяет состояние UI, а не фиксированную паузу.

## Smoke, Actions и диагностика

```bash
bash scripts/smoke/run.sh http://127.0.0.1:3000
(cd frontend && npx playwright test --list)
(cd frontend && npx playwright show-report)
```

Smoke проверяет auth/chat/media/WS, включая реальные cookie-сессии. Для него нужны
curl, Python 3 и Go версии из `backend-v2/go.mod`. Проверка oversized sticker pack
выполняется только при заданном `MAX_FILE_SIZE` в соответствии со стендом.

Workflow `.github/workflows/e2e.yml` запускается только вручную и не является
обязательной проверкой PR. Secrets: `E2E_BASE_URL` (backend/proxy target для Vite
и smoke), `E2E_USER_A`, `E2E_USER_B`, `E2E_PASSWORD`, `E2E_CLOUD_PASSWORD` при отличии
облачного пароля. Необязательный input `base_url` — адрес уже работающего клиента.
Расписание и label-триггеры не включены. При ошибке сохраняются HTML-отчёт,
trace, видео и скриншоты. `.auth/state.json` содержит cookies, игнорируется git
и не загружается в артефакты.
